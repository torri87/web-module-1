Модулі

Які модулі ви створили та за що вони відповідають?

    store/orders-store.js: Відповідає виключно за збереження та управління даними в пам'яті (масив замовлень, додавання, пошук за ID, отримання всіх, видалення). Не містить ніякої HTTP-логіки.

    services/orders-service.js: Відповідає за бізнес-логіку застосунку — валідацію вхідних даних замовлення (validateCreateOrder), нормалізацію полів, розрахунок загальної суми (calculateTotal), генерацію унікальних ID та форматування відповідей.

    routes/: Модуль маршрутизації (контролери), який приймає HTTP-запити (req, res), викликає необхідні методи сервісу та сховища, формує відповідні HTTP-статуси (200, 201, 204, 400, 404) та заголовки.

    app.js: Конфігурація та ініціалізація Express-застосунку, підключення глобальних middleware, роутів та централізованого обробника помилок.

Очищення коду

Що ви видалили або змінили? Чому?

    Винесли монолітний код із єдиного файлу app.js у чітко відокремлені модулі за принципом єдиної відповідальності (Single Responsibility Principle).

    Позбулися дублювання логіки та змішування шарів (тепер HTTP-запити не залежать напряму від структури масиву, а бізнес-логіка не знає про об'єкти req/res).

    Виидалив функції штучної затримки роботи.

API-контракт

Як ви перевірили, що зовнішня поведінка не змінилася?

    Запустив автоматизовані тести командою npm test, які повністю покривають усі бізнес-правила та сценарії API (успішне створення, валідацію помилок, коди 404, 204 тощо).

    Виконав тест навантаження командою npm run load, який підтвердив стабільну роботу (Failed: 0) та високу швидкість відповіді всіх ендпоінтів.

    Перевірив, що формати запитів/відповідей, статус-коди та заголовки (Location) залишилися абсолютно ідентичними початковим вимогам.
